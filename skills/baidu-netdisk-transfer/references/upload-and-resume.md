# 接口边界与恢复

OpenAPI 的依据：
https://pan.baidu.com/union/doc/基础网盘服务/上传/分片上传/
https://pan.baidu.com/union/doc/基础网盘服务/上传/获取上传域名/
https://pan.baidu.com/union/doc/基础网盘服务/上传/预上传/

2026-11-01读取的规则：普通用户分片固定4MB、单文件4GB；会员分片最大16MB、
单文件10GB；超级会员分片最大32MB、单文件20GB。实现采用4MiB倍数和更保守的
十进制文件上限。2000片是本工具的保守准入预算，绝非宣称百度全接口官方上限。
实际会员身份从当前接口返回取得，不由本地旧记录或另一台机器推测。

事故样本：22,091,005,014字节，8MiB需要2634片，两次约2040片停滞；
16MiB变为1317片，仅预创建成功，原材料未提供最终合并成功证明。
因此不能把“调大到16MiB”当成完整解决；该文件还超出了上述OpenAPI总大小限制。
Cookie、网页、原生客户端分别核定能力。不能从2040附近的现象推导统一2048上限。

web v1复用本机客户端登录，仅接≤256MiB、4MiB分片、≤64片的有限范围。
这是本工具的小文件工作范围，未声称测出了账号的实际最大值。客户端会员编码
（例如21）保留原值，不转换成OpenAPI的0/1/2。超范围的auto方案在上传前转原生客户端。
web合并使用该接口的type=2；不能照搬OpenAPI的rtype作为合并模式。

原任务记录包含：源身份、完整SHA256、分片MD5、精确目标、账号指纹、
uploadid、需要上传的序号和逐片ACK。uploadid及ACK属于本机私有状态，Git不收录。
控制请求先保存意图；只有响应中的数据实际保存后才报告可恢复。出现结果未知，
保留现场并用只读远端查询或原生观察核实，不以新precreate代替健康检查。

上传域名通过当前任务的locateupload取得；仅在服务端有效期内缓存，不能把示例
PCS主机永远写死。每片记录服务端回传MD5，合并使用这些实际回执，最后仍以独立
下载SHA验证完整字节。HTTP 200网页、预创建200、已发送字节都不是最终成功。

等待策略：连接10秒、读响应60秒、单HTTP请求90秒；只重试网络错误、429和5xx，
最多3次并遵守Retry-After；服务端要求超过60秒时保存断点暂停，不提前重试。
控制请求不盲目重试。180秒无新ACK停止新派发，
在途有界请求结束后返回PAUSED。原生客户端的异步任务使用原进度，不强杀共享进程。

ETA仅在最近窗口持续新增ACK时估算；同时报告最后确认时间、确认片数/字节、
剩余片数和错误。停滞时报告暂停/诊断，不能继续承诺“再等20分钟”。

## 低空间冷备份：先核回收收益，再生成归档

上传源来自APFS克隆时，先用local-disk-maintenance核数据叉独占量、共享块和
实际容量。逻辑4GiB的副本可能几乎不占独占空间；重新打包却会产生数GiB新块，
不能把“上传后删除源”预估为相同大小的可用空间增长。压缩文件资源叉另外计量。

冷备份计划必须列出可回收证据、源文件清单、元数据保全方法、分卷上限及
本地暂存峰值。低空间下使用有界暂存窗口：每卷生成前、独立下载前重新读取
当前容量，只预留该卷生成、独立验证和既定底线所需空间；不能只在开始时
检查一次、随后把整套归档与回下载同时留在本地。先保全源内容，收益为零
或不足以覆盖暂存的候选不应作为紧急腾空间方案。

分卷传输受原后端限制，每卷沿原task.json、账号、路径、uploadid及ACK继续。
单卷VERIFIED仅证明该卷的独立字节验证；全部分卷还需要按清单重组、检查
压缩流完整性并核还原文件集与SHA，才可称整套可恢复。可流式验证以减少
空间占用，但不能省略独立下载或把源文件自己的SHA当作远端验真。

紧急情况下可按当前授权回收自己生成、源资料仍完整保留的可再生暂存。记录
已移除的精确路径与SHA、保留远端回执，并将整体任务标为未完成。原task的
源路径被移除后不得盲目resume；先重新生成并核完整内容与原身份要求，不
改写原上传回执、不伪造“全量已备份”。

## doctor按通道分别判定

若同一份doctor输出同时出现OpenAPI的AUTH_EXPIRED（errno=20016）与
web_connection_verified=true、client_credentials_readable=true、recommended_backend=web，
分别报告“OpenAPI凭据过期、当前web检查通过”，不把它归为全通道离线，也不自动
重登或重建凭据。读取本次checked_at和limits；limit_kind=local_small_file_scope_not_vendor_maximum
表明256MiB/4MiB/64片是本地保守范围。只在此范围内规划，超范围沿原生客户端；
一次doctor通过不替代实际传输和独立下载验真。

在precreate之前按精确字节数计算`ceil(size / chunk_bytes)`，同时核本次limits的
max_file_bytes、allowed_chunk_bytes和max_chunks。256MiB/4MiB正好是64片，
不能只核文件大小而漏掉片数。超出本通道范围沿原生客户端，不修改分片大小
硬凑准入；改变分片方案须另记新尝试，保留原task与ACK，不能当原任务续传。
